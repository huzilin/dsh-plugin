# 单据状态机（plan 视图五类单据）

> 更新：2026-09-21。词表正本 = plan-protocol 第三节；本文是插件视角的汇总镜像（解析口径 + 流转 + 计数口径）。状态词允许附注（如「已关闭（复测 PASS）」），插件取首词判色、附注独立展示。

## 1. 工单（ticket，frontmatter `status`）

```
open（开票）→ claimed（认领/派发，写 claimed_by + session）→ resolved（落码完成）
                └────────────────→ out_of_scope（不做/移出）
```

- 插件归一词表：`doing/in_progress/wip/in review` → claimed；`done/closed/complete/completed/shipped` → resolved；`abandoned/rejected/wontfix/cancelled/superseded` → out_of_scope；其余 → open。
- 未关单 = open + claimed（tab「🗺️ 地图 / 🎫 工单」计数口径）。
- QA 标记（2026-09-21 增）：frontmatter `qa_cases: true`（测例已构建）、`qa_tested: true`（测例已执行）、`qa_accepted: true`（验收通过）——卡片/详情以徽标展示；写入时机见 to-qa-testcases / run-qa-testcases。
- 执行登记（2026-09-21 增）：开工即 `status: claimed` + `claimed_by` + `session`（DSH `session-<uuid>` / zcode `sess_<id>`）；session 决定跳转（DSH）或恢复命令复制（zcode）。

## 2. 待拍板文档（approval，frontmatter `status`，协议五态）

```
pending（待拍）→ closed（拍板结算）
              → superseded-by:<path>（被新文档取代）
              → abandoned（废弃不作）
```

- `active` 是活文档态（spec/map/台账等长期文件），不是拍板流转终点。总览/地图 tab 计数 = pending 数。

## 3. 挂账（ledger，正文 `- 状态:` 行）

```
在挂（活债）→ 已销（处理完 / 迁出留痕）
           → 已转票（恢复入原图立票，落点写在来源字段）
```

- 一账一文件：全局 `.plan/ledger/挂账-NN-slug.md`、图内 `.plan/<effort>/ledger/`；台账 tab 计数 = 在挂数；台账页默认筛「在挂」。

## 4. 缺陷（qa-defect，正文 `- 状态:` 行，六词）

```
待修复 → 已确认 → 修复中 → 待复测 → 已关闭
                ↘ 挂起（不修，附注理由）
```

- 一缺陷一文件：`.plan/<effort>/qa/DEF-NN-slug.md`；缺陷 tab 计数 = 非「已关闭/关闭/挂起」的条数。旧单文件多小节形态只读兼容。

## 5. 图与 spec（map.md / spec.md，frontmatter `status`）

```
active（活图）⇄ closed（收口 = 该图全部票 done；挂账恢复可重开）
superseded-by:<path>（被新图取代）
```

## 横向纪律

- 「未关」态驱动 tab 计数（工单 open/claimed、拍板 pending、挂账 在挂、缺陷 待修复~待复测）；「关」态必须留痕不删文件。
- frontmatter `status` 管文档层，正文字段行管条目层，两层不混。
- 测试关联（2026-09-21 增）：`qa/cases.md` 一图一份不拆文件，由路径识别为 `cases` 类单列「🧪 测例」子页；测例与票的覆盖关系在串联画布按「票 NN」引用自动连线。
