## 一、盲区类型学（语义库）

| 类型 | 定义 | 典型信号 | 对应防线（to-qa-testcases SKILL.md 节） |
|---|---|---|---|
| B1 oracle 缺源 | 测试设计依据里少了某个「预期来源」，该来源描述的行为整类不可见 | 原型/设计稿差距成批漏网；spec 非 AC 章的明文要求无用例；用户说过的话再次被漏 | 「设计依据盘点」七源盘点 + 双向映射 |
| B2 通道单一 | 只有协议通道（API/DB），渲染结果无人看 | 纯视觉/布局/默认态问题全靠用户截图 | 「双通道」+ 红线：纯协议不得对 UI 出通过（执行侧截图记录归 run-qa-testcases） |
| B3 断言停在协议层 | 只断言「接口按契约返回」，不断言「业务按意图串联」 | 每个接口都对、整条业务链是断的；角色在该步拿不到业务上需要的东西 | 「断言三维」业务语义层 + 写读联动 sweep |
| B4 文档-实现漂移 | 裁决/实现已变，文档仍旧口径 | docs 类缺陷由用户核查时顺带发现 | 七源盘点第 5 源（设计文档）须与裁决正本互验 |
| B5 验证环境 ≠ 用户验收环境 | 测试在自造数据/隔离环境全绿，用户实际浏览的环境数据从未被同一套期望校验 | 用户在联调/演示环境点开即坏；「安全隔离原则」反过来成了没人巡检用户环境的理由 | D-3 用例设计（本 skill Process 第 2 步）+ 执行侧巡检准出（run-qa-testcases） |

## 二、案例

### CASE-003 · novel telemetry-viz 呈现腿首执行：脏书 id 弹错漏网（2026-09-23，novel）

**背景**：telemetry-viz 票 01（统计页迁 ECharts）首轮只跑了协议腿（11/11 绿），呈现腿因「无视觉模型 + Playwright 资产未建」被显式降险留格。用户 2026-09-23 授权 agent 代理执行呈现腿（原话「A，好不好看，你们有什么范式么，可以自己判断」）。
**事件**：新建 Playwright 资产并首执行，17 条里 16 绿、1 红——红在 **P-13**（新补的用例）：localStorage 存的书已不存在时，统计页连弹两条「对象不存在」。根因=「章筛选下拉读大纲」的 effect 对 404 走 `showError` 弹错，与「顶栏书回落」存在竞速窗口。**该缺陷在协议腿全绿时完全不可见**（协议腿只打端点、不进页面）。
**关键判断**：这不是「协议腿跑得不够」，而是**通道缺失**——纯协议通道按红线本就不得对 UI 出「通过」，但首轮把呈现腿留格后，该留格在实践中等于「该页无 UI 断言」，既有页面的降级路径无人看。
**归因**：
| 层 | 盲区 | 缺的东西 |
|---|---|---|
| 呈现通道缺席 | B2 | 首轮 P 组只设计未执行；降级路径（脏值/空态/竞速）无真浏览器断言 |
| 断言只覆盖正路径 | B3 | 原 P 组 12 条全是「切到有数据的书」正路径，缺「选中书已消失」这类**前置脏态** |
**反事实**：B2 防线（双通道 + 红线）若在首轮就建资产执行，本缺陷首轮即可见；本轮补的 P-13 即该防线的落地形态。
**衍生**：①`cases.md` P 组补 P-13（前置脏态类），并登记「测试设计缺口」回写；②沉淀一条通用坑：**依赖「当前选中实体仍存在」的页面，须有「实体已消失」的降级用例**。
**证据指针**：`.plan/qa/DEF-12-脏书id弹对象不存在.md`（含 E 节最小复现入口 `qa/run-e2e.sh P-13`）；验收档案 `.plan/telemetry-viz/qa/test.md` §2 过程有效性。

### CASE-002 · wbflow 联调库产物全外链（2026-09-10，dsh-flow，紧接 CASE-001）

**背景**：CASE-001 复盘刚结束、门禁 skill 刚建成，用户随即发现联调库 req-004「全是外链」。
**事件**：联调库 artifacts 表 9/9 行 kind=link、href 为假域名 `https://docs.example.local/...`，document 类 0 行；seed 40 节点 expected_outputs 全为 `kind:"document"`。FE 对 link 不进阅读器（无正文、无锚定评论），用户点开即死链——文档阅读→锚定评论→评审整条核心交互在用户环境不可达。用户约束「挂载的产物文档不能是外链，必须是系统内部入库的产物」此前反复口头提及，但 spec/arch/semantica 无正本。
**QA 当时做了什么**：在 scratch 库用真实 fixture（document 类）跑了 API 正文回读 + 产物矩阵，全绿。
**归因**：
| 层 | 盲区 | 缺的东西 |
|---|---|---|
| 约束不在 oracle | B1 | 用户反复说过的规则未转成断言，也未落 spec |
| FE 交互零覆盖 | B2 | 无呈现通道，link/document 在阅读器里的行为差异从未被看见 |
| 只验自己造的数据 | **B5（新）** | 「不触联调库」的安全原则同时意味着联调库从未被期望矩阵校验；D-1 若跑在联调库会 9/9 FAIL |
| 系统无守卫 | （产品缺陷）| 登记与推进判据都不对照 expected_outputs 的期望 kind，外链可冒充文档一路推进 |
**反事实**：七源第 6 源（用户批注）+ 呈现通道 + B5 巡检，三者任一即可提前发现。
**证据指针**：`dsh-flow/docs/v1.0/qa/qa-defects.md` BUG-015（含审批材料与最小复现入口）。
**衍生**：新增 B5 类型与对应防线；to-qa-testcases 骨架 D 组增 D-3「用户验收环境数据合规巡检」。

### CASE-001 · wbflow v1.0 全量验收轮（2026-09-10，dsh-flow）

**背景**：QA 以独立黑盒驱动（HTTP + scratch 库 SQL 对账）验收 rd 服务：28 端点 × 4 流程 40 节点 × 分支 × 对账，末轮 188 PASS / 0 FAIL / 1 SKIP，且抓出 S1 死锁（plan 流程尾段）与 S2 竞速（幽灵评审位）。
**事件**：同期用户经看板巡检 / 浏览器亲测 / 原型对照批注，发现 9 条缺陷（含 2 条 S2/P1），QA 轮全部未命中。
**关键判断**：执行不是问题（覆盖自检 checklist 全过、缺陷均有 DB 实证），问题是**设计依据清单本身缺维度**——checklist 查的是用例写得好不好，从不查预期来源全不全。

**逐条归因**：

| 用户发现 | 盲区类型 | 缺的具体东西 |
|---|---|---|
| 详情页需求说明沉底无渲染；flow 页布局；评审药丸不可点；变更历史形态（4 条） | B1 | oracle 无原型：设计依据只列 spec / 契约 / 架构文档 / seed，m2/m4 原型从未进清单，「实现 vs 原型 diff」从未发生（用户原话「你要自己完整的 diff 一下差异」） |
| 流程树点色不编码门禁结论 | B2 | 被测对象写的是「rd 服务」，FE 不在范围；纯视觉问题 API/DB 通道结构性不可见 |
| 需求状态与流程推进零联动（S2/P1） | B1+B3 | spec §7.3 明文「收尾→已完成」不在 AC 章，覆盖映射只做了「§4.1 AC + 注记 A-H」；走查断言维度（相位/current_node/last_decision/gate/round/通知）无一条跨表联动 |
| 评审节点拿不到被评审产物（S2/P1） | B3 | A-13 认真断言了 relatedNodes 三向——断言的是「接口返回什么」，不是「评审者这一步业务上需要什么」；seed 能力 how 写「读输入：被评审设计文档」只是文字，无程序断言承接 |
| 评审评论可游离不锚文档 | B3 | anchor 四级契约测过，业务规则「评审场景必须锚文档」没测；用户原话「所有的评审都是挂在文档上的」 |
| arch_design 未同步注记-A；branch 协作口径过期（2 条 docs） | B4 | D 组对账只对账 DB，不对账文档与裁决正本 |

**反事实**：七源盘点（第 2 源 spec 全文行为清单、第 4 源原型、第 6 源用户批注）+ 断言三维业务语义层 + 呈现通道，9 条可提前发现 9 条。
**互补观察**：QA 通道独占命中「判据完整性 / 接口口径 / 竞速窗口」（S1 死锁仅黑盒全量能稳定复现）；用户通道独占命中「业务语义 / 上下文完整性 / 视觉交互」。目标不是取消用户验收，是把后者左移到出结论之前。
**证据指针**：`dsh-flow/docs/v1.0/qa/qa-defects.md`「发现源统计」节；`qa-test-cases.md` L4-5（设计依据清单）、L74-75（走查断言维度）。
**衍生**：建 test-design-gate（本 skill 前身，2026-09-20 随技能族合并并入 to-qa-testcases）；决策溯源 semantica `a432efd6`。
