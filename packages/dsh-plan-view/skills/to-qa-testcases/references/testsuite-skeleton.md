## 一、《用例设计》`.plan/<effort>/qa/cases.md`

> 落点：`.plan/<effort>/qa/cases.md`（effort = 有 `map.md` 的计划目录；无 effort 的项目按其 docs 惯例放 `qa/cases.md`）。可执行脚本资产不进 `.plan/`，留仓库 `qa/`（要进 CI、跟代码走）。
> **文档形态**：本文件**不加 frontmatter 状态头**——qa 三件套中只有 `defect.md` 加头（`type: qa-defect`，规定见 `run-qa-testcases` 的缺陷台账骨架），本文件与 `test.md` 保持纯正文形态，不被 plan 视图识别。

### §2 用例总览与覆盖矩阵
| 组 | 覆盖 | 用例编号范围 | 覆盖的 AC / 行为条目 | 重点 |

| U 用户批注回归 | [历史批注逐条] | U-01~ | | 长期保留 |

### §3 用例明细（按组）
每条：`编号 | 对象（接口/节点/页面）| 场景/步骤 | 断言（协议层 / 业务语义层 / 呈现层）| 预期（可判定）`。
B 组每步额外列「写读联动」：本步写了什么 → 哪些读方必须同步变化。

**P 组单列（有 UI 必设；章节名固定「P 组 · 页面预期验收」）**：B 组管「链走得通」，P 组管「页面看起来对不对、用起来对不对」——两组并列、互不替代（B 组绿不代表 P 组绿）。**P 组全为呈现腿，不得以协议腿代出「通过」**；每条设计时即预留截图位（含整页首屏），截图在执行轮落 `qa/screenshots/`。内部两表分列，不合并：

| 表 | 回答的问题 | 断言维度（逐元素位过一遍） |
|---|---|---|
| **P-1 UI 呈现** | 看起来对不对 | ① 位置（在页面/区块的哪一处，与相邻元素同排不换行不重叠）② 文案逐字（标签/占位/空态/浮层/提示条——错一字即 ✗）③ 形态（字号层级、色彩系、默认态/展开态/选中态、徽标与视觉编码）④ 空态（无数据时给什么，不是空白）⑤ 长列表/多选项时是否撑破布局 |
| **P-2 使用交互** | 用起来对不对 | ① 操作可达（一次点击即开，不卡顿）② 反馈（写操作后立即回显 + 提示条文案与类型，不刷新页面）③ 持久化（刷新后仍生效，非前端假象）④ 失败路径（错误提示中文可读 + **乐观更新须回滚到库真值**）⑤ 降级语义（辅助功能失败不阻断主流程，且提示可见）⑥ 起点正确（弹窗/表单打开时预选值=该对象当前值，可改可清）⑦ 文案正交 sweep（不与相邻概念的措辞混用） |

**P 组准出**：每个元素位至少 1 条 P-1 + 1 条 P-2；文案类断言截图须能看清文字；同一元素位的失败/降级路径必有一条。

## 二、可执行资产 `qa/`（三原则）

| 资产 | 要求 |
|---|---|
| `env_up` / `env_down` | scratch 隔离（独立库/命名空间，绝不触联调库）；迁移 + seed；凭据环境变量注入零落地；down 幂等清理。**造数纪律**（真实接口链路构造、禁 SQL 直插业务表、造不到=SKIP）见 `run-qa-testcases/references/data-construction.md`，建 seed 前必读 |
| 驱动脚本 | 软失败收全（单断言失败不中断）；用例编号可过滤单跑；结果 json；退出码 FAIL>0 非 0。有 UI 项目呈现通道用 Playwright 形态，正本 `to-qa-testcases/references/playwright-assets.md` |
| 诊断最小环 | 逐缺陷独立可跑（秒级），作为 defect.md E 节 cmd 的载体（E 节契约见 run-qa-testcases 缺陷台账骨架） |
| 基线记录 | PASS / FAIL / SKIP + SKIP 附因；写进 `qa/README` |
| `qa/README.md` | 资产清单 + 复跑三步 + 扩展约定（新增用例/剧本怎么加） |
