### §3 用例明细（按组）
每条：`编号 | 对象（接口/节点/页面）| 场景/步骤 | 断言（协议层 / 业务语义层 / 呈现层）| 预期（可判定）`。
B 组每步额外列「写读联动」：本步写了什么 → 哪些读方必须同步变化。

**P 组单列（有 UI 必设；章节名固定「P 组 · 页面预期验收」）**：B 组管「链走得通」，P 组管「页面看起来对不对、用起来对不对」——两组并列、互不替代（B 组绿不代表 P 组绿）。**P 组全为呈现腿，不得以协议腿代出「通过」**；每条设计时即预留截图位（含整页首屏），截图在执行轮落 `qa/screenshots/`。内部两表分列，不合并：

|---|---|---|

## 二、可执行资产 `qa/`（三原则）

| 资产 | 要求 |
|---|---|
| `env_up` / `env_down` | 并发按维度隔离（业务域维度：电商=商品、写作=书，各测例集各占不同维度值；独库/独立命名空间 = 维度取「环境」的可选实现，非默认要求）；维度与具体数据集声明进 cases.md §0 与 `qa/README`；迁移 + seed 可一键重建（污染即重建自愈）；凭据环境变量注入零落地；down 幂等清理。**造数纪律**（真实接口链路构造、禁 SQL 直插业务表、造不到=SKIP）见 `run-qa-testcases/references/data-construction.md`，建 seed 前必读 |
| 驱动脚本 | 软失败收全（单断言失败不中断）；用例编号可过滤单跑；结果 json；退出码 FAIL>0 非 0。有 UI 项目呈现通道用 Playwright 形态，正本 `to-qa-testcases/references/playwright-assets.md` |
| 诊断最小环 | 逐缺陷独立可跑（秒级），作为 defect.md E 节 cmd 的载体（E 节契约见 run-qa-testcases 缺陷台账骨架） |
| 基线记录 | PASS / FAIL / SKIP + SKIP 附因；写进 `qa/README` |
| `qa/README.md` | 资产清单 + 复跑三步 + 扩展约定（新增用例/剧本怎么加） |

### 资产可复用模式（协议通道驱动脚本）

- `ck(cid, cond, detail)`：软失败断言——失败只记 `RESULTS`，不抛异常，一轮收齐全部缺陷；`skip(cid, reason)` 显式跳过必附因；
- `Req` 对象：把 create / assign / update / review / decide / advance 全步骤封装成方法，剧本函数只写业务序列，不重复 HTTP 细节；
- `WALKED` 列表：每条走完的需求 append 进去，末尾 D-1 产物矩阵对账自动遍历——**新增剧本零成本进对账**；
- `main()`：结果 `json.dump` + `sys.exit(1 if fail else 0)`，直接接 CI；
- **库态对账**：`sql()` 只读直查测试库；`audit_count(table, row, action, field, by)` 按审计行计数对账「谁在何时改了什么」——竞速类缺陷靠 audit_log id 先后序实证。

### 等待与确定性红线（全通道资产强制）

> 缘起：固定死等多次真实致损——条件早满足则空耗，条件晚满足则假红，且执行通过也要烧满等待时长。凡「等某事完成」的等待，一律条件探测。

1. **禁固定死等做就绪判定**：`sleep N` / `time.sleep(N)` / `waitForTimeout(N)` 不得用作「等某事完成」——条件早满足则空耗，条件晚满足则假红。豁免两类（须注释说明）：轮询内的**采样间隔**（判稳需两次取样的固定间隙，如弹层动画连续两次等宽）；第 5 条的**负向观察窗**。
2. **就绪判定 = 条件探测**：先定义「什么信号代表就绪」（终态字段 / 元素可见 / 回包落文件 / 窗口收敛），再以**探测间隔 + 次数或时长上限**轮询，条件满足**立即退出**，不再等满。
3. **三形态惯用法**：
   - shell：`for i in $(seq 1 上限); do 探测 && break; sleep 间隔; done`（env_up healthz 探活同款）；
   - python：`for _ in range(上限):` / `while time.time() < deadline:` + 命中即 `return`（seed 脚本 `poll_task` 形态）；
   - Playwright：优先自动重试断言（`toBeVisible` / `toHaveCount` 内建轮询+超时）；自定义条件用 `expect.poll`（`intervals`=探测间隔、`timeout`=上限）；裸 `waitForTimeout` 作就绪判定 = 违例。
4. **超时即红**：上限耗尽 = FAIL，附最后观测值；禁静默吞超时继续跑、禁降级成 SKIP。
5. **负向断言（断「不出现」）**：瞬态 toast 类无法瞬时证伪，允许显式有界观察窗，但窗口起点须锚定「前置条件完成」信号（如回落 Tag 在位），不锚定盲等；有永久性信号可替代的（如 4xx 响应监听）以永久信号为确定性门。
6. **数据前提探测**：依赖数据的用例按数据可用性探测选对象（书/章/任务），禁写死 id；无数据如实 SKIP 附因，不伪造通过、不记产品缺陷（正本 `run-qa-testcases/references/data-construction.md`）。
7. **收割整树**：后台长驻进程（管道 / acp / BE）留 PID，结束（含红路超时）按 `pgrep -P` 递归整树 kill，两路都不留残留。

### 并发与环境红线（全通道资产强制）

> 缘起：并发事故多次真实复现——同机多套测例环境互斥互耗、盲目复用存量进程把环境事件记成用例红、临时物落系统临时目录被定期清理即假红。测例资产默认必须**可并发**。

1. **数据并发按维度隔离，不按库**：不要求每测例集独立库/命名空间——按被测业务域选定**并发控制维度**（电商域=商品、写作域=书），同环境并行的各测例集各占不同维度值；**头部声明三件套，缺一不达标（写进 cases.md §0 与 `qa/README`，防后续偏移）**：①并发控制维度是什么（如：书）；②数据集唯一 id=具体实例——具体书 id/书名（运行时生成的 id 由构建脚本产出后回写登记位、头部登记当前实例，**禁只声明 `-<ts>` 模式不报实例**）；③构建该数据集的自动化脚本路径（一键重建，真实接口链路造数，正本 `run-qa-testcases/references/data-construction.md`）；测试内容即 cases.md §2/§3 用例集本体。数据可一键重建（脚本即③），维度值被污染即重建自愈。独库/独立命名空间仍可选（= 维度取「环境」的实现方式之一），采用时库名带测例集标识。机器资源零共享不变：端口、工作目录、容器与进程名一律带测例集标识（同一端口号如 `:8098` 只归一个测例集）；资源清单（端口号/库/目录路径）登记进 `qa/README`。两套测例集同机并行互不干扰是默认态，不是可选项。
2. **临时工作目录显式声明，禁系统临时目录**：工作根目录写死在 `env_up` 与 `qa/README`（推荐仓库内 `qa/<集名>/.work/`，或 `$HOME/.cache/<project>-qa/<集名>/`），`mkdir -p` 幂等创建；**禁 `/tmp`、`/var/tmp` 等系统临时目录**——运行中被系统清理即假红。
3. **占用预检**：`env_up` 起服务前先探测目标端口/库名占用，被占即 FAIL 附占用者（`lsof` 等），禁把未知存量进程当自己的环境复用。
4. **`env_up` 幂等**：从零可重建、重复执行不残留脏态——先按资源清单 down 掉自己的旧实例再 up；构建步骤（迁移 + seed + 就绪信号）在 `qa/README` 成文。
5. **`env_down` 只清自己**：按资源清单清理——杀自己留的 PID 整树（同「等待与确定性红线」第 7 条收割整树）、删自己的库/目录/容器；他人资源即使占着同名端口也只备案不动手。
6. **构建与清理必须成文**：环境怎么建（步骤 + 就绪信号）、怎么清（清理项清单）写进 `cases.md` §0 与 `qa/README`，禁口口相传。
7. **互斥须声明**：确因资源受限无法并发的（端口段固定、依赖同一外部件等），`qa/README` 显式声明「与 XX 互斥」+ 原因；未声明即默认可并发。
