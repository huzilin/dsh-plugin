# 验收五维 DoD 与 UI 走查纪律

> 正本迁移自 OpenViking preferences（2026-09-12 收编）。来源：2026-09-12 novel 双状态机验收复盘（用户质问「接口通路但页面崩了/高亮不显眼算什么验收」——此前验收只覆盖功能维度，视觉/交互/原型一致/边界四维空白）。

## 五维 DoD（验收合格定义，缺一不可）

1. **功能正确**：状态流转/数据落库/API 契约符合预期（单测+接口走查）。
2. **视觉质量**：高亮醒目程度、对齐无错位、无元素重叠、空态合理——**必须浏览器看渲染结果**，DOM/ARIA 树验证不能替代。
3. **交互语义**：按钮/入口在当前状态该不该出现、文案与语境匹配、操作反馈明确（例：to_review 态不该有「发起 AI 审校」按钮——状态机语义审查）。
4. **与真相源一致**：交互形态对照原型蓝本（novel: fe/prototype/app-prototype.html）、字段口径对照 spec/定稿——实现完成后逐项对照，不以票面降级口径为准。
5. **边界异常**：空态/失败态/并发/极端输入。

## 纪律

- **降级须显式拍板**：拆票时写「从简/暂不支持」类降级，必须列「降级项+影响+待拍板」；验收按原型原要求验，不按降级口径验——防「自己降级自己验」自证循环。
- **FE 交付必要步骤**：浏览器渲染走查 + 截图留档；浏览器工具点击/截屏失败时用 evaluate 驱动或 web-gui-tester skill 绕过，不得退回「DOM 验证通过」交差。
- **清单预期双断言**：每步预期 = 功能断言（状态变成什么）+ 视觉断言（醒目程度/对齐/反馈），写清单时用用户视角。
- **清单模板**：novel `.plan/state-machine/人工验收清单-20260912.md` 头部已挂五维 DoD，后续验收清单照此模板。
- **负路径全组合矩阵（2026-09-12 第三次追问后追加）**：凡交付状态机/动作端点，必须同时交「动作×起始态全组合矩阵测试」（oracle=domain 边表/状态真源；合法必成落目标态、非法必拦截且状态不变）。**禁止用「domain 层有单测」回应「端点要覆盖」**——两层必须分别列覆盖证据（novel 范本：`TestUnit_CommentActions_NegativePathMatrix`，56 组合）。
- **「已覆盖」声明必须附覆盖矩阵**（2026-09-12 追加）：宣称某层测试已覆盖时，必须列出「层 × 路径 × 组合」的覆盖清单作为证据；部分覆盖（如仅 domain 纯函数）不得表述为「已覆盖」，用户反馈的关闭必须附证据，否则不得标「已处置」。
- **信息溯源纪律（2026-09-12 用户定性「严重的失职」后追加，普适命令级）**：**任何返回给用户的信息，返回前必须溯源确定**。信息只有三类合法来源：①代码/文档事实（grep/读文件实证，附位置）；②测试实证（测试名+断言+结果）；③真机实证（浏览器/接口实测，附输出或截图）。不满足者只能以「未验证/我的推断」的显式标注返回，**不得以肯定语气交付**。「代码写了+build 绿」不等于「功能生效」——UI 改动的生效证明 = 浏览器实测。每次向用户汇报前自查：本条信息的来源是三者中哪个？答不出 = 不许说。
- **状态机文档化纪律（2026-09-12 用户拍板追加，普适命令级）**：凡设计/实现/修改**任何状态机**（业务状态机、执行过程态、结果态、联动闸口），必须：①定义严格通路——每个状态列明准入动作（什么能做）与轮转（从哪来到哪去），非法组合显式拦截；②**过程态与结果态分开定义**（如 task.state 的 queued/running 是执行过程，pass/classification 是执行结果——禁止混用文案）；③**必须落文档**（状态机文档是核心设计物，不是代码注释）；④**必须同步用户**（产出后给用户过目，不是只进 git）。范本：novel `.plan/state-machine/执行状态机设计-AI审校修复链.md`（三层状态全景+链路严格通路+动作准入矩阵+已知口径）。
