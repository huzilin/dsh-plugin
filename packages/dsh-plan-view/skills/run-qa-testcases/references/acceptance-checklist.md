# 验收清单具体化

- 偏好人工验收/测试清单具体到「点哪里、看到什么」：写清确切的数据对象/章节/页面、认哪张卡（按文字开头）、点哪个按钮、应变成什么状态。
- 未构造数据的对象或章节要明确标注，不给无法定位的测试对象。
- 偏好先核对真实数据现状并改名成好认的名字，再给出可执行指引。
- 清单中不得残留内部 id 表述（如「资源 114」），统一用切换器/界面可见的对象名与章名，让读清单的人无需知道任何 id 即可定位。

**交付前自检三问**：①每条清单对象能否零 id 定位（书名/章名/按钮文字）？②有无残留内部 id 表述？③未构造数据的对象是否显式标注（联动造数禁令 SKIP 口径）？

清单预期用双断言（功能断言+视觉断言），见 acceptance-dod.md「清单预期双断言」。
