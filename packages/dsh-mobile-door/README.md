# dsh-mobile-door

让手机 / iPad 访问只监听本机回环地址的 DSH Web。插件在局域网端口上同时做两件事：
**发凭据**（第一次打开时）和**反向代理**（之后所有请求转发给回环上的 DSH）。

不需要手抄终端里那条带 token 的登录链接，也不需要改 DSH 的监听地址。

## 为什么需要它

DSH Web 的进门流程是「带 token 的链接 → 换取凭据（cookie）」。两件事卡住手机访问：

1. **拿不到那条链接**：桌面端形态看不到终端。
2. **DSH 根本连不上**：Web 服务器只绑回环地址，手机访问局域网 IP 是连不通的。

而让 DSH 改绑局域网地址这条路走不通——桌面外壳写死连 `127.0.0.1`，DSH 又不接受
`0.0.0.0` 通配地址，改绑之后桌面自己就打不开了。

所以插件不去动 DSH 的监听，而是自己在局域网端口上接收手机的请求，完成认证后转发
给回环上的 DSH。

## 怎么工作

```
手机 → http://192.168.x.x:8899
        ① 没有凭据 → 插件回一个页面，页面写入凭据后跳回来
        ② 有凭据  → 插件把请求转给 127.0.0.1:<DSH端口>，把响应原样交回
```

手机地址栏始终停在 8899，DSH 自己的端口从不对外暴露。

### 转发时改写了什么

DSH 会校验请求的来源，直连时靠浏览器天然满足，经代理转发就必须由插件补上：

| 项 | 为什么改 | 怎么改 |
| --- | --- | --- |
| `Host` | DSH 的地址栅栏只信回环地址 | 改成 `127.0.0.1:<DSH端口>` |
| `Origin` | DSH 要求 Origin 必须等于 Host | 改成 `http://127.0.0.1:<DSH端口>` |
| `Referer` | 同上 | 改成回环起点 + 原路径 |
| `Cookie` | DSH 把凭据**绑在 Host 上**，浏览器带来的是插件针对 8899 签的那张，DSH 不认 | 摘掉插件凭据，换成回环 authority 的凭据 |
| WebSocket | 实时通道走 `upgrade` 事件，普通请求处理碰不到 | 单独转发升级，握手后两端直接对接 |

最后一条尤其关键：不转发 WebSocket，界面能打开，但前后端连不上，页面是死的。

### 凭据

用 DSH 自己的签名密钥签发，格式与 DSH 的 browser-auth 一致：

| 项 | 规则 |
| --- | --- |
| 签名密钥 | `$DSH_HOME/.credentials.yaml` 里 `client-connection/browser-session` 的 `secret`（32 字节 base64url） |
| cookie 名 | `dsh-auth-` + base64url(sha256(authority))，authority = `主机:端口` |
| cookie 值 | `v1.<base64url(JSON 载荷)>.<base64url(HMAC-SHA256 签名)>` |

凭据里有两张纸，各管一段路：

- **浏览器那张**绑 `192.168.x.x:8899`，插件自己校验，决定「是否放行到代理」；
- **转发那张**绑 `127.0.0.1:<DSH端口>`，插件每次转发时现签，DSH 用它认账。

凭据文件缺失或形状不符时插件不监听端口并报错，绝不用错的密钥签发一张永远 401 的
凭据。

## 配置

在 profile 的 `cordis.patch.yml` 里同 id 覆盖 `config`：

```yaml
- id: dsh-mobile-door
  config:
    door: true          # 打开代理入口
    doorPort: 8899      # 代理入口端口；0 = 系统分配
    days: 400           # 凭据有效期，不得超过连接插件的 cookieMaxAgeDays
    targetPort: 0       # 0 = 用 DSH Web 实际监听的端口
```

DSH 保持默认配置即可（绑 `127.0.0.1`，桌面端正常工作）。

## 安装

```sh
dsh plugin --profile <名称> add 'github:huzilin/dsh-plugin#path:/packages/dsh-mobile-door'
```

装完冷启动一次 DSH。启动日志会打印可用地址：

```
[dsh-mobile-door] 代理入口：http://192.168.3.197:8899  http://100.103.217.67:8899
```

手机连同一个 Wi-Fi 打开其中一条即可。走 Tailscale 的话用 100.x 那个地址。

## 安全边界

- 只在配置的端口上服务；没有有效凭据的请求只会拿到一个发凭据的页面（POST 等
  带副作用的请求直接 403），不会转发给 DSH。
- 转发出去的凭据是插件现签的，浏览器那张不会被带进 DSH。
- **入口本身不做认证**——它就是个发凭据的地方，所以只在可信网络里打开；不用时把
  `door` 改回 `false`。

## 已知限制

- 若连接插件把 `cookieMaxAgeDays` 调得比本插件的 `days` 小，DSH 侧会拒绝转发过来的
  凭据；两处要保持一致。
- 凭据按主机名绑定：换了 Wi-Fi 导致 IP 变化后，用新地址重开一次即可。
- 代理不缓冲响应体，也不做压缩/重写；DSH 发什么就交回什么。
