> 正本关系：目录条款正本 = plan-protocol §三（本档是它的**写入视角速查表**，不 duplicate 条款正文，冲突以协议为准）；取代《梳理-文件类型与获取总表-20260928.md》行 50 旧口径（`.plan/<slug>/assets/`）。
> **修订（2026-09-30 收拢拍板）**：全局审批档由 `.plan/` 根层散放收拢为 `.plan/approval/`（全局件审批成员目录化，与 effort 内 `approval/` 同形）；根层 `待拍板-*`/`已拍板-*` 前缀形状降为存量兼容，正文各节已按此更新。

## 〇、两层 tree（拍板版速写）

```
<repo>/
├── .scratch/<effort-slug>/     # effort 层：map.md / spec.md / issues/ / assets/ / approval/ / qa/ / ledger/
├── .plan/                      # 全局层：approval/ 审批档 + qa/ + ledger/（+ handoffs/ 存量豁免）——永不装 effort（2026-09-30 收拢拍板：审批档由根层散放收拢为 approval/）
├── docs/research/              # 全局调研/复盘（全局场景≠全局件，本档即首份按此落位者）
├── docs/requirements/          # 需求文档（文件名 <effort-slug>-<主题>.md）
├── .tmp/handoffs|audits/       # 一次性杂项，出检索面
└── .archive/rounds/<round-id>/ # 归档轮（整树快照，唯一合法搬移终点）
```

识别判据（全部可机械检查）：**effort 判据** = `.scratch/` 子目录含 `map.md` 或 `spec.md`；**qa 白名单** = `type: qa-defect` frontmatter 或 `cases-*` 固定名；**票目录唯一** = `issues/`（旧 `tickets/` 违例）；**目录封闭清单** = effort 内七成员，清单外即违例。

## 一、effort 层（`.scratch/<effort-slug>/`）

### `map.md` — wayfinder 图
- **生成**：`wayfinder` skill（开图会话建首批票时一并建）。
- **场景**：新一轮探索立项。`to-tickets` **不建 map**（2026-09-29 拍板「to-tickets 不自动补 map」，无 map 目录由 plan-lint 检查[2]守门）。
- **形状**：五节——`## Destination` / `## Notes` / `## Decisions so far`（done 票一行 gist + 相对链接）/ `## Not yet specified`（雾，粗体标题 + 可省 clears-with）/ `## Out of scope`。无状态字段，读正文即状态。

### `spec.md` — 实施规格
- **生成**：`to-spec`（grill/推演对话收尾时）。
- **场景**：拍板结论需要落成实施规格；每节写归宿行（`> **归宿（日期）**：→ arch §x ＋ docs/<file> §x`）。
- **形状**：七节模板（Problem/Solution/User Stories/Implementation Decisions/Testing Decisions/Out of Scope/Further Notes）。无状态头；void 判据 = 每节有归宿行且目标存在 + 所属 effort 票尽；被取代标 `superseded-by:`。

### `issues/NN-<slug>.md` — 唯一票目录
- **生成**：`wayfinder`（开图建首批 + 收口 create-then-wire）；`to-tickets`（spec/待拍板 → 实施票，依赖序一次写全）。
- **场景**：一切要干活的票。**四票型同居一目录**：`task / research / prototype / grilling`，type 写 frontmatter、不分目录。
- **形状**：`NN-<slug>.md` 一票一文件，01 起编号，编号即身份永不复用。frontmatter：`type` + `blocked_by: []`（裸值）+ `claimed_by/claimed_at`（认领时）+ 可选 `undermined_by` / `assets`。推演票正文 `## Question` 开头、收口追加 `## Answer`/`## Ruled out`（状态派生：有 prose 即 done/out_of_scope）；task 票 `# NN: 标题` + What to build + 验收 checkbox + frontmatter `status:`（open/claimed/done）。
- **终态**：只关不删；`plan-loop`/`plan-sync` 盘点 frontier。

### `assets/` — 调研证据
- **生成**：research/prototype/grilling 票**执行中**的调研会话（WebSearch/WebFetch 等产出）。
- **场景**：票的调研产物落这里，同时把路径写进该票 frontmatter `assets: [<repo 相对路径>]`——「经票挂链」是唯一检索入口。
- **形状**：无状态引用式 Markdown（每断言带出处）；**不带四字段状态头**。不进票面、不被视图当票。

### `approval/` — effort 内审批档
- **生成**：`grill-with-doc`（拷问收口）/ `wayfinder`（图内拍板）。
- **场景**：**归属本 effort** 的拍板（区别于全局性审批 → `.plan/` 根层）。
- **形状**：`待拍板-<slug>-<date>.md`，四字段头（type: approval / date / status / origin）。结算由 `plan-approve` 翻 status: closed；翻标挂点（`archived: <归宿>`）与全局档同机制；随 effort 整轮归档。

### `qa/` — 图内测例与缺陷
- **生成**：`to-qa-testcases`（cases.md 测例集）；`run-qa-testcases`（test.md 执行记录，按编号逐条，末轮为准）；`diagnosing-bugs`（`DEF-NN.md` 一缺陷一文件）。
- **场景**：基于本图实施票构建测例 / 执行 / 缺陷管理（挂账启测线由 `run-qa-testcases` 编排）。
- **形状**：`cases.md` / `test.md` **无 frontmatter**，固定名 + H1 形状识别，测例按编号 grep 直达；`DEF-NN.md` 带 `type: qa-defect` + `status` 双写（frontmatter + 正文 `- 状态:` 行）。

### `ledger/` — 图内台账
- **生成**：任意会话挂账（无专门 skill；登记时守挂账启动条件纪律）。
- **场景**：明确属于本图的跨票债务（做不了/暂不做的）。
- **形状**：`挂账-NN-<slug>.md` 一账一文件，`type: ledger` + 状态头 + 正文固定四行 `- 状态:`（在挂/已销/已转票）、`- 卡点:`、`- 启动条件:`、`- 来源:`——字段行是解析契约，不得改形。

## 二、全局层

### `.plan/approval/待拍板-*.md` / `已拍板-*.md` — 全局性审批档
- **生成**：`to-approval`（全局性拍板：跨图 / 无 effort 归属 / 治理类）。
- **场景**：结论要人拍板且不归属单一 effort。2026-09-30 收拢拍板：由 `.plan/` 根层散放收拢为 `approval/` 子目录（与 effort 内 `approval/` 同形）；根层前缀形状仅存量兼容，plan-lint 检查[9] 对根层报违例驱动迁移。
- **形状**：`待拍板-<slug>-<date>.md`，四字段头 status: pending；结算 `plan-approve` 翻 closed 并改名 `已拍板-*`。
- **终态**：含 spec 项 → `to-spec` 完成后翻 `archived: <spec 落点>`；纯结论档 → grill inline 结算翻；已标者随轮归档，未标者留。

### `.plan/qa/` — 全局缺陷与回测
- **生成**：`run-qa-testcases full`（整页/跨图回测 → `cases-<主题>.md`）；`diagnosing-bugs`（无图归属缺陷 → `DEF-<effort-slug>-NN.md`，编号全局唯一）。
- **形状**：`DEF-*` 带 `type: qa-defect`（无此头不被视图识别）；`cases-*` 固定名前缀。

### `.plan/ledger/` — 全局台账
- **生成**：任意会话挂账（跨图 / 环境 / 架构类）。
- **形状**：`挂账-NN-<slug>.md`，契约同图内台账；常驻不随轮归档（全局件）。

### `.plan/handoffs/` — 存量豁免
- **只读兼容**，不再新写；新交接落 `.tmp/handoffs/`。

## 三、effort 外的文档层

### `docs/research/` — 全局调研/复盘（本档所在）
- **生成**：任意会话的调研/复盘收口（无票归属、非审批）。
- **形状**：四字段状态头（status: active/closed），引用式正文。**docs 是长期权威区**——过程性结论须归宿到 arch/权威文档，过程档本身留这里备查。

### `docs/requirements/` — 需求文档
- **生成**：需求整理会话（to-spec 前置或独立）。
- **形状**：`<effort-slug>-<主题>.md`（文件名必须含 effort slug，与 `.scratch/<slug>/` 同名可检索）；用户故事 / Problem / Solution / 验收与测法 / 范围外。

### `.tmp/handoffs|audits/` — 一次性杂项
- **生成**：会话收尾交接 / 审计产物。出仓出检索面（`.zcodeignore`）；有留存价值转 `.archive/` 或 `.plan/`，不默认驻留。

### `.archive/rounds/<round-id>/` — 归档轮
- **生成**：`plan-archive`（唯一搬移者）。
- **场景**：轮完成四判据（票尽 + qa_accepted、缺陷全关、台账全消、spec 已标/审批清）。
- **形状**：整轮 `git mv`，目录结构原样（相对引用随树存活）；`README.md` 轮次索引；成员头部 `archived: <round-id>`。出检索面，获取 = 显式考古。
