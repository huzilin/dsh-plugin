# ADR-0001：草稿优先与自主领票两通道并存

plan 生态的原红线「点按钮只把指令填进输入框、人确认后再发送，不做后台静默派活」曾是全局禁止。2026-09-26 用户裁定：自主领任务执行与该红线**不构成冲突**——两条执行通道并存分工：**草稿优先**降格为兜底 + 拍板/grill 等人机响应场景的入口；**自主领票**（agent 自主领取 open 票执行）升为常态通道。宿主无通知能力，状态获取与打扰一律走**周期自查询**（轮询），不做外部通知渠道。

## Considered Options

- 废除红线、无任何分工（拒：失去默认安全底线）；
- 红线不动、自主只在 plan-loop 单会话内跑（拒：把自主降格为例外，与「常态通道」定位不符）；
- 冲突框架下的「例外开关/总闸」（被裁定取代：不是权限冲突，是场景分工）。

## Consequences

- 红线文本须从「全局禁止」改写为「场景分工」，涉及代码域（输入桥头注释、派活机制正本）与文档域（plan-protocol、相关记忆正本）双域 sweep——待落地。
- 恢复宿主自动发送接口（历史上被本插件主动退役）成为自主通道的候选拼图，风险与载体选择见设计访谈文档 R2-Q1。
- 术语定义正本：`CONTEXT.md` 执行通道节。
