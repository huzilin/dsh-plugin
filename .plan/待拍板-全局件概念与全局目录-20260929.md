## 二、待拍板项（Round-1 frontier，五项）

### Q1 概念定名——是否正式设立命名概念、叫什么

- **是什么**：把散落的「全局性落点」升格为一个有名字、有定义、有判据的公共概念，还是维持散落条款现状。
- **从哪来**：用户原话「要看创建一个公共的概念，我们维持全局 plan 么」；冲突一/二/三均为无定义导致的表述漂移实证。
- **影响什么**：协议 §三/§四 的行文组织、各 skill 引用措辞、后续新场景（如「全局 prototype 资产」）有没有唯一判据可依。
- **选项**：
  - **A. 设名「全局件」**（推荐）：协议与视图文案已自发用这个词，正名成本最低；定义节落 plan-protocol §三（跨仓契约正本，与状态词表同处），本仓 CONTEXT.md 不收（域不同，避免双正本）。
  - **B. 设名但换词**：如「常驻件」「根层件」「全局 plan 区」。语义同 A，但需 sweep 掉已出现的两处「全局件」既成用法。
  - **C. 不设名**：维持散落条款，只修冲突一/二两处表述。零新增概念，但 novel 式冲突会复发——每个新仓库/新会话重新猜一遍。
- ➡️ **推荐 A**：词已存在，补定义即可；定义节内同时消解冲突一/二。

> **【拍板 2026-09-29】Q1 = 可以（A）**：设名「全局件」，定义节落 plan-protocol §三，CONTEXT.md 不收。

### Q2 范围——全局件封闭清单

- **是什么**：哪些对象算全局件。若 Q1 选 A/B，需定封闭或开放。
- **从哪来**：用户列举「research、挂账、qa 三个全局场景」与协议现状的比对。关键差异：**research 的全局形态有意不进 `.plan/`**（挂 `docs/research/`，有自己的 `active/closed` 生命周期）；handoffs/audits 明确非 plan 生态。
- **影响什么**：全局件目录白名单、plan-lint 是否可校验、以及「全局 ≠ .plan」这条边界要不要写死。
- **选项**：
  - **A. 封闭三件套**（推荐）：全局件 = ①根层审批档（`.plan/待拍板-\*` / `已拍板-\*`）②`.plan/qa/`（`DEF-\*.md` + `cases-\*.md`）③`.plan/ledger/`（`挂账-NN-\*.md`）。research/handoffs 显式写为「全局场景但非全局件」（各自有归宿）。新场景入清单须修订协议。
  - **B. 开放枚举**：只给判据（跨图、无 effort 归属、常驻不随轮），新场景可自行落 `.plan/` 新子目录。灵活，但 novel 的 `.plan/research/` 旧病会复发——判据拦不住「图省事丢 .plan」。
- ➡️ **推荐 A**：判据型开放枚举正是 novel `.plan/research/` 事故的成因；封闭清单才能被 plan-lint 机械守门（联动 Q4）。

> **【拍板 2026-09-29】Q2 = 可以（A）**：封闭三件套（根层审批档 + `.plan/qa/` + `.plan/ledger/`）；research/handoffs 写为「全局场景但非全局件」。

### Q3 判据优先级——effort 判据（含 map.md）与全局件相撞时谁赢

- **是什么**：「目录含 map.md = effort」这条判据，遇到全局件目录（或 `.plan/` 下任何目录）时的适用边界。
- **从哪来**：novel 冲突三（原文见零）；协议现行写法只说「`.scratch/` 下目录里有 map.md 才被当作 effort」，对 `.plan/` 下含 map.md 的目录没写。
- **影响什么**：所有存量仓（novel 等）迁移批的裁决依据；视图对 `.plan/` 下含 map.md 目录的加载行为定性（现行 `loadPlanMerged` 会把它当图渲染——novel 测线图因此可见，这其实是期望行为）。
- **选项**：
  - **A. 全局件豁免 + 存量兼容（推荐）**：①全局件三目录**豁免** effort 判据——即使内含 map.md（历史遗留内嵌图）也不触发迁移令，图按存量旧布局继续可读；②`.plan/` 下**非全局件**子目录含 map.md = 存量旧布局 effort，只读兼容，迁不迁归用户推进的存量迁移批次（协议既有口径，不变）；③写侧唯一合法 effort 落点仍是 `.scratch/<slug>/`（不变）。①②③合起来即 novel 冲突的普适裁决。
  - **B. 判据一律优先**：`.plan/` 下任何含 map.md 目录都算 effort、都应迁 `.scratch/`。全局件目录内嵌图也得拆。novel `.plan/qa/` 就必须拆分（联动 Q5 的 B 选项）。
- ➡️ **推荐 A**：全局 qa 资产与其内嵌测线图同生命周期，强拆制造两个目录、一处引用；豁免条款让 novel 已做的保守解直接成为正解。

> **【拍板 2026-09-29】Q3 = 可以（A）**：全局件目录豁免 effort 判据；`.plan/` 下非全局件子目录含 map.md = 存量旧布局 effort（只读兼容）；写侧唯一合法 effort 落点仍为 `.scratch/<slug>/`。novel 冲突的普适裁决。

### Q4 plan-lint 守门——加不加「.plan 根层白名单」检查

- **是什么**：若 Q2 选封闭清单，plan-lint 是否新增检查：`.plan/` 下出现清单外子目录（新建的）即报（存量 `.plan/<effort>/`、`handoffs/` 豁免）。
- **从哪来**：novel `.plan/research/` 曾长期存在、直到目录迁移批才被人工发现——判据写在了迁移 prompt 里而非机械门禁里。
- **影响什么**：plan-lint.sh（vendored 源 + 同步出去的安装副本）；「协议明文 plan-lint 对审批档零检查」条款不受影响（查目录形状，不查审批档内容）。
- **选项**：
  - **A. 加**（推荐）：一条目录名白名单检查，成本低；是「封闭清单」能维持的机械保障。
  - **B. 不加**：靠协议纪律。省一处脚本维护，但回到人肉发现模式。
- ➡️ **推荐 A**：封闭清单无门禁等于没封。

> **【拍板 2026-09-29】Q4 = 加（A）**：plan-lint 新增检查 [6] `.plan` 根层白名单——清单外子目录即报；豁免 `handoffs`（存量）与含 `map.md` 的子目录（存量旧布局 effort 兼容）。

### Q5 novel 实例处置——`.plan/qa/` 双重身份的终局

- **是什么**：novel `.plan/qa/`（全局缺陷锚点 + 内嵌「全页面人工验收测线」effort 图 + 2 个 closed 审批档）维持原地还是拆分。
- **从哪来**：novel 会话保守解「整目录不动」，并明言「若你希望它迁 `.scratch/qa/`，一个小 commit 即可补做」——该仓在等本会话结论。
- **影响什么**：novel 仓一个 commit（或零改动）；semantica `90bb0996` 决策的确认或推翻；视图里该测线图是否继续以图形态可见。
- **选项**：
  - **A. 维持原地双重身份**（推荐，依赖 Q3=A）：零改动；测线图继续可见可读；全局 DEF 锚点不动；2 个 closed 审批档留原地作历史锚点（协议既有口径）。semantica 决策由「推断」转「确认」。
  - **B. 拆分**：全局 DEF/cases 留 `.plan/qa/`，内嵌测线图迁 `.scratch/<slug>/`。目录语义纯净（全局件目录不再内嵌图），代价是一个迁移 commit + 相对引用巡检 + 视图上测线图换位置。
- ➡️ **推荐 A**：拆分收益仅剩目录语义纯净，而 Q3-A 的豁免条款已把「内嵌图」定义为合法存量形态；为纯净付迁移成本不划算。

> **【拍板 2026-09-29】Q5 = 可（A）**：novel `.plan/qa/` 维持原地双重身份、零改动；semantica `90bb0996` 由「推断」转「确认」。
