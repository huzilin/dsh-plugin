## 状态标识机制判定：header 字段 vs 正文标题派生（2026-09-28）

**问题**：统一用 header（frontmatter 字段）做标识是否更好？wayfinder 推演票的状态与行文中的标题标记（`## Answer` / `## Ruled out`）对齐——哪种是更好的实现？

**答案：不存在「统一」的最优解——按「该状态是否由内容唯一决定」拆分，两种机制各管一半：**

| 判据 | 用正文标题派生（wayfinder 式） | 用 header 字段（执行票/DEF/挂账式） |
|:--|:--|:--|
| 状态**由内容唯一决定**（done = 答案已写；out_of_scope = 已判越界） | ✔ **更好**：状态与内容是同一份事实，**无第二副本可漂移**；「写答案即关票」，没有第二次编辑可忘；不一致**不可表示** | ✘ 字段会撒谎：body 已有 Answer 而 status 仍 open 的票**可以存在**（#1099 实证：implement 干完不翻字段的正是这个形态） |
| 状态**内容推不出来**（claimed=谁持有；ready-for-agent=准不准入；严重度/Assignee） | ✘ 正文表达不了——硬派生只能外加约定（原版本地形态的 `Status:` 行就是这么来的） | ✔ **更好**： possession/路由/工单属性天生是元数据，字段是它们唯一的家 |

**各自的已实证失效面**：
- header 字段的失效 = **漂移与遗忘**：#1099（implement 干完不翻状态）、DEF/挂账「frontmatter status + body 状态行」双写（同一事实两处，正是 TRACKER:7 警告的「second copy…goes stale in one of them」）；
- 正文派生的失效 = **形状脆弱**：2026-09-03 out_of_scope 事故——写手即兴发明 `out_of_scope: true` + `## Status：Ruled out` 的非契约形状，解析器落回 open；派生要求**每个写手都精确遵守闭节形状**，自由发挥即静默失效。

**结论（本表采用）**：
1. **内容态（done / out_of_scope / open）→ 正文标题派生**——wayfinder 推演票是对的，且应作为方向：执行票的 `done` 实际也可由「验收清单全勾」派生（内容决定），现状用字段属双轨遗留，票 09/plan-protocol 收编时统一；
2. **持有态与工单属性（claimed_by / claimed_at / ready-for-agent / 严重度 / Assignee / type）→ header 字段**——这些是内容推不出来的路由事实，字段是它们唯一的家（wayfinder 自己的 claim 也是字段）；
3. ~~禁止双写：同一状态不得同时存在于 header 与正文（DEF/挂账的 status+状态行双写列入 plan-protocol 收编清理项）~~ **〔2026-09-28 用户裁定：维持原版设计，本条与「执行票 done 派生化」一并冻结不执行**——读文件头与读标题行无成本差异，双轨维持现状；DEF/挂账双写保持现状。**拍板 1（同日）**：获取条款**全部落 plan-protocol**，并按需配置加载场景（识别到代码开发/代码检索即加载）——已执行：plan-protocol 摘除 `disable-model-invocation`（使识别触发式加载可行）+ description 增补触发场景（代码开发/代码检索读写 plan 文档时加载），install-skills.sh 已同步安装态（生效需新开会话）；「文件类型与获取」条款正文随票 09 迁移定稿后写入。**最终裁定（同日，用户两段指示合成）**：`disable-model-invocation: true` **保留不摘**；加载触发改走全局 AGENTS.md 常驻指令（ponytail 式：「读写 `.plan/`/`.scratch/` 计划单据或跑 plan 系流程前，先加载 plan-protocol」；Skill 调用被门禁挡时直读其 SKILL.md 等效）——即**非模型自动触发，由常驻用户指令驱动加载**。description 的场景清单保留作编排参考。
4. **派生的代价是形状契约**：闭节形状必须写死在 plan-protocol 并由 plan-lint 机械校验（对冲 09-03 类即兴形状）——派生的可靠性不靠写手自觉，靠 lint。
5. **派生不要求读全文**：状态检查走结构标记 grep（`grep -LE '^## (Answer|Ruled out)'` 返回文件名清单，正文零进入上下文）；全文仅在 zoom（要解决该票/要其答案）时读，且票尺寸被「一票一会话」约束封顶。无 frontmatter 类（cases/test）识别靠固定名 + H1 形状，且状态不翻转、结论前置（test.md §1）——无重复查态成本。派生的真实代价在「消费端各自实现派生规则」的一次性代码成本与工具路径纪律，不在每次读取。
6. **植入路径（让 agent 按上式获取状态）**四层：L1 skill 文本内嵌命令（TRACKER-MARKDOWN 已含，✅原版已植入）；L2 协议条款（plan-protocol 收编时把本表「状态获取」列写入正文，票 09 时做）；L3 **脚本封装（最可靠，建议随票 07 施工）**——提供 `plan-frontier <effort>` 脚本：剥围栏/滤 claimed/编号排序一条命令完成，agent 无需记语法；L4 hook 硬门禁（zg-gate 先例）备而不用（zoom 读全文合法，拦不动也不必拦）。**本仓执行通道注**：zg-gate 拦 Bash 裸 grep——命令实际经 `zvec_grep_rg`（rg 语法）执行或 `ZG_FALLBACK=1` 声明，植入文本须写明此通道。
7. **「没加载 skill」的退化路径与冗余防线**：未加载≠失明——agent 退化为 `ls`+`Read` 逐票凭标题猜（布局自解释，大概率猜对，但写侧易即兴破坏形状、读侧费 token）。防线刻意不押在加载上：L2 协议住在仓库（探索 `.plan/` 或读 README 必被指到 plan-protocol/TRACKER）→ 布局自解释 → plan-lint 事后必抓 → plan view 由代码派生（人不被误导）。加载只是最便宜的通道；**推论：把获取条款收编进 plan-protocol（L2）比依赖 skill 加载更接近必然被读到**。另注：wayfinder 等 `disable-model-invocation: true` 的 skill 模型永不自动加载（原版有意，user-invoked 只做编排）。

## 三·补、目录与编号规范细化（2026-09-28 六条批复 + 额外条款；本节细化 A–D 表的落点与标识，冲突处以本节为准）

**1. 调研/复盘文档目录**（已拍，按批复修正）：`.plan/` 在老协议中**专门放审批文档**，不污染其语义——调研/复盘**不进 `.plan/`**，落 **`docs/research/<name>.md`**（挂文档树、文档地图可指；四字段头照旧，`status: active/closed` 区分在役/留档）。

**2. 词汇表过期标记**（已拍）：词条三态——**`active`（在役，默认零标注）/ `deprecated`（废弃，无替代）/ `superseded-by:<新词条|docs 路径>`（被替换，必须写去向）**。规则：「X 废弃」不合法，必须「X → Y」；非在役必须显式标注；plan-lint 可选校验 deprecated 无去向 → warn。plan-protocol 收编时同步 CONTEXT-FORMAT。

**3. ADR 识别与废弃归档**（已拍，含读前拦截）：识别 = `docs/adr/NNNN-<slug>.md` + **frontmatter 必填化**（`id: NNNN` / `status: proposed|accepted|deprecated|superseded by ADR-NNNN` / `date`），**在头部标记**。**废弃归档：原地标记，不搬**。**读前拦截**：ADR 消费端（improve-codebase-architecture 及一切引用 ADR 的环节）读前先查 `status`——`deprecated/superseded` 直接拦截，转读替代 ADR，禁止照废弃案开工。

**4. 测例编号与执行标记**（已拍）：每条测例**必须有唯一编号** `<腿前缀>-NN`（协议腿 D-NN / 呈现腿 P-NN / API 腿 A-NN），effort 内唯一。**快速定位要求**：编号必须以可 grep 的固定形状出现（`### <编号>` 标题或表格行首列），**禁止只存在于段落行文中**——agent 按编号 `grep` 直达该测例，零遍历。执行状态记在 test.md 按编号逐条（PASS/FAIL/SKIP + 轮次）；**run-qa-testcases 支持按编号子集精确重跑**（`--cases P-13,P-07`，内部同样按编号 grep 定位）。

**5. 执行记录多轮**（已拍）：同一 test.md 内按轮次追加（每轮一节），「末轮为准」，不开新文件。

**6. 缺陷编号全局唯一**（已拍）：`DEF-<effort-slug>-NN`（如 `DEF-dna-craft-05`），文件名/frontmatter/行内引用全用全号；存量改名一次性迁移（归入票 09）。

**6b. 一次性交接/审计 → `.tmp/`**（已拍）：`.tmp/handoffs/`、`.tmp/audits/`（出仓出检索面）；有留存价值 → 转正 `.archive/` 或留 `.plan/`，不默认驻留。

**7. 目录对齐总则**（已拍）：官方有的（spec/map/issues）→ `.scratch/<feature-slug>/`；官方没有、**与 effort 挂钩**的（qa/ledger/assets）→ `.scratch/<feature-slug>/qa|ledger|assets/`；官方没有、**全局性**的（审批档留 `.plan/`；调研复盘 → `docs/research/`；全局 qa/ledger → `.plan/qa|ledger/`）；一次性杂项 → `.tmp/`。

**额外（已拍）：审批档吸纳后标记归档**——拍板结束（closed）后，结论被 spec 或全局文档**吸纳**；吸纳完成时审批档必须翻 `status: superseded-by:<归宿路径>`（spec 落点或 docs 落点），复用既有五态词表、**不新增状态**。生命周期：`pending → closed（拍板落定）→ superseded-by:<归宿>`（注放完成）。plan-lint 可选校验：`closed` 且其结论已被后续 spec 吸收却长期未标归宿 → warn。

## 归档机制明确化（plan-archive 现行 + 新裁定下的修订点，2026-09-28 triage）

### 现行机制（plan-archive SKILL.md 全文实测，113 行）

- **单元 = 轮（round）**：输入端（grill/wayfinder）→ 落地收尾（implement + plan-sync）一次闭环；**整轮一次归档，不散件**（轮内互引成网，散件必拆断）。
- **成员**：effort 目录（map+tickets+assets）+ 该轮待拍板散件 + handoff/过程文档。
- **轮完成判据（三条全满足）**：①轮内票全 `done`（plan-sync 对账完）；②待拍板全 `closed`/`superseded-by:`/`abandoned`；③无仍被活跃文档作依据的未决内容。
- **触发**：手动，永不自动（`git mv` 不可逆，触发权在用户）。
- **九步**：①列候选轮+成员清单交用户确认 → ②建/更新 `.archive/README.md`（轮次索引+现行权威两表）→ ③整轮 `git mv .plan/<成员> .archive/rounds/<round-id>/<成员>`（结构原样，round-id=`YYYY-MM-DD-<主题>`，git log --follow 可溯）→ ④轮内引用改相对路径 → ⑤**轮外引用 sweep 改指新位**（含 `.archive/` 自身、docs、CONTEXT、正本文档；文件名+全路径两遍）→ ⑥仍被实现引用的成员就地偏差声明留原处+README 登记 → ⑦过时结论就地三要素标注（谁取代/何时/留有什么用）→ ⑧更新 README 两表 → ⑨一轮一 commit。
- **禁止**：不自动跑 / 不改代码 / 不新写 spec / 不删文件 / 不散件归档。

### 补充裁定（2026-09-28 第二批）

- **R1 头部归档标识**：归档成员**必须做头部标识**——frontmatter 增 `archived: <round-id>`（无头文件在首行加 `<!-- archived: <round-id> -->` 注释）。作用：任何 agent 直读该文件（哪怕脱离轮上下文、哪怕检索命中）第一眼即见「已归档、勿据以实现」——对齐「标识必须写在头部」与 ADR frontmatter 必填化同款逻辑。写入动作归入归档九步之③（git mv 同批完成）。
- **R2 删除步⑤（轮外引用 sweep 改指）**：前提 = 全量权威已收敛 docs、权威文档**禁止持有指向 tracker 区（`.plan/`/`.scratch/`）的引用**（spec 已一次性化 + 归宿行 + 禁反向指向）——归档时轮外**不应存在**指向成员的活引用，sweep 改指的动作对象不复存在。步⑤降级为「**断链巡检（只报不改）**」：发现轮外活文档仍指被归档成员 = 登记协议违例（回溯写侧纪律），**不代改**。
