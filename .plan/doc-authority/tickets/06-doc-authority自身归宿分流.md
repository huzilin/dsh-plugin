# 06 `doc-authority` 自身归宿分流（自指验证）

## 交付什么

用本方案自己定的规则**结束本方案**：把 `.plan/doc-authority/spec.md` 按五类归宿分流到长期权威层，随后作废归档。

## 为什么需要

**这是本方案唯一的自指验证**。整份方案断言「归宿行机制可机械判定『更新完成』」「spec 用完即可作废」——**如果这套规则连自己都收不了尾，它就不成立。**

`spec.md` §Further Notes 已自述此事：

> 本 spec 是 `.plan/doc-authority/` 的一次性实施文档；其产物是协议条款。**协议条款落地后**，本 spec 按五类归宿分流（决策类→arch 或领域文档；过程物→归档），随后作废。

## 具体内容

| 步 | 动作 |
|:--|:--|
| 1 | 给 `spec.md` **每节补归宿行**（四类取值，写在各节标题下） |
| 2 | 按决策 4 五类分流：测试决策→需求文档；Out of Scope→需求文档；实现细节→docs（横→arch／纵→领域文档）；DDL→领域文档；过程物→归档 |
| 3 | **验证「更新完成」判据**：每节有归宿行 且 目标存在——两者皆满足方可作废 |
| 4 | spec 状态头翻 `closed` 或按生命周期作废；过程物移入 `.archive/` |
| 5 | **回扫本 effort 全部文档**（map／票／待拍板档），逐份标注去向 |

## 依赖说明

`blocked_by: [01, 02, 03, 04, 05]` —— **分流的前提是协议条款已落地**。若 01~05 未完成，spec 的内容**无处可去**（归宿行的目标不存在），此时作废等于丢结论——**正是本方案要根治的那个病，不能自己犯**。

## 验收标准（外部可观察）

1. `spec.md` **每节都有归宿行**，无遗漏节；
2. 每条归宿行的**目标确实存在**（脚本可查）；
3. 分流后**长期权威层可独立读懂本方案结论**——不依赖已作废的 spec；
4. `.plan/doc-authority/` 内**无 `status: pending` 的残留待拍项**；
5. 本 effort 全部文档状态真实（无「已作废却仍留 open」）。

## 诚实边界

- 本仓**无 `docs/architecture.md`**（实测只有 `CONTEXT.md`）——若分流时「横向」内容确有落点需求，**是否新建 arch 正本属实施判断**，须先与用户确认，不得擅自新建；
- 本票**只处理 `doc-authority` 这一个 effort 的文档**，不回扫其他 effort。
