## 五、第二轮问题（4 问）

### R2-Q1 执行载体：自主领票的票怎么跑

**这是什么**：裁定 1 定了「自主领票是常态通道」，但没定**载体**——agent 领了票，在哪儿、怎么把它执行掉。这是宿主能力约束下必须选的（底座 1/2）。

- **A 单会话连跑**：你在视图点火一次，agent 在一个会话内按 plan-loop 连续领票执行，直到可执行桶空或碰到拍板点停下。零宿主改动、今天就能落地；缺点：串行一次一张、会话死了循环就停，要人重新点火。
- **B 每票一会话 + 自动驱动**：恢复宿主自动发送接口（底座 2），循环器自动为每张可领票开会话并直接驱动，可并行、票间隔离、单会话死只影响一票；失败自动降级 = 草稿预填 + 周期查询提醒你来兜底（正好用上裁定 1 给草稿优先定的兜底角色）。缺点：恢复的是当初因风险退役的能力，且并发会话烧 token。
- **C 分两步走**：先 A 落地，B 作为二阶段（自动发送恢复单独立票，不阻塞 A）。

**无论选哪个**：视图提供循环的**停止按钮**（操作面，非权限闸，见裁定 1 推断）。

**影响什么**：A 决定近期全部实现的形态；B 牵动宿主接口重启与安全设计；C 把风险切开。

**➡️ 推荐 C**：A 先行见效，B 立项演进。

### R2-Q2 展示主线（原 Q2 剩余 + Q5a）

**这是什么**：你要「优化展示、管理全流程」，自动刷新已结算，剩下方向（可多选）：

- **a. 流程主线活视图**：把说明页那条静态全流程图变活——按 .plan 实况高亮每一环（决策循环几个 pending、几张票执行中/done、QA 走到哪、哪些挂账可启动），点环节直接跳对应单据。这是「全流程管理入口」最正面的一块。
- **b. 单据纵深**：点开一张票能看到全生命周期（谁拍的板、哪轮执行、QA 轨迹、哪轮归档）。
- **c. 票↔会话双向联动**（原 Q5a）：现在只能从票跳会话；反过来在会话头部能看到「这个会话正领着哪张票、干到哪」，点过去就是票面。自主领票常态后，这个反向视图是你盯进度的主窗口。
- **d. 其他**：你直说哪里不好用。

**➡️ 推荐 a + c**：a 管「一眼看全」，c 管「自主跑起来之后怎么盯」；b 后续票。

### R2-Q3 必要打扰清单（原 Q4 剩余）

**这是什么**：「只在必要时打扰」的「必要」由你定。通道已结算（周期自查询：页面横幅/角标 + 循环会话内简报），剩下**哪些事件**触发打扰（多选）：

1. **待拍板**出现（协议本就要求人拍，属既有义务的提醒）
2. **自主循环卡死/连败**停下
3. **收口简报**（一批票 done / 一轮跑完的决策就绪摘要）
4. **缺陷登记**（QA 或自主执行中测出缺陷立档）
5. **整轮走完**提醒归档（协议规定归档永不自动）

**➡️ 推荐 1+2+3+5 必扰；4 可选（缺陷只进视图缺陷页，卡住实施时才升格打扰）**。

### R2-Q4 按需落文档边界（原 Q6）

**这是什么**：协议已写明 agent 可自主写什么（票状态/缺陷档/台账/测例）、必须人拍什么（待拍板文档）。**空白是**：自主模式下 agent 能不能改 **spec.md / map.md / 已拍板审批档的正文**——这些是你拍过板的定案，agent 改写 = 事后篡改拍板记录。

- **A 冻结定案类**：自主模式禁改 spec / map / 审批档正文与状态头；发现定案本身有问题 → 立**待拍板**文档交你，不得自己改。
- **B 允许小修**：可改但必须留修订注记。风险：拍板记录被静默改写，违背「原文照抄」纪律。

**➡️ 推荐 A**。将写进协议与自主通道的硬边界。
