## 一、原文照抄与语境

**你的原话**：

**「侧边栏」在这里有歧义，我按两种理解都准备了方案**：可能指左边那一列（会话/工作区导航），也可能泛指右侧栏本身。方案 A 对应「左边一列的一级按钮」，方案 B 对应「一次点击直达，不再走 + 菜单」。

## 三、DSH 留好的两个挂载位（都不是我造的，是官方扩展点）

### 位一：左侧栏的「全局面板」图标行

- **是什么**：左侧栏在「新建会话」按钮下方、会话列表上方，预留了一行图标按钮，专门用来放**全局面板**（global panel，指占据中间那一大块区域、与对话平级的整页视图）。点一下，中间区域整块从对话切换成该面板。【文档已写明：`ui-sidebar/src/client/contract/slots.ts` 的 `sidebar.panellist` 槽位注释】
- **现在有几个面板**：**一个都没有**。DSH 自带的全局面板数量为零，所以那一行现在压根不渲染。【实测：全仓库 + 全部已装插件检索 `sidebar.panellist` 的注册者，只有测试代码】
- **代价**：见下面方案 A 的影响——打开全局面板会顶掉对话，并且**右侧栏整块消失**。

### 位二：左侧栏底部的「页脚动作」位

- **是什么**：左侧栏最底下、设置齿轮旁边的一个按钮位。【文档已写明：`ui-sidebar/src/client/contract/slots.ts` 的 `sidebar.footer.action` 槽位】

- **好处**：它只是「一个按钮」，点了干什么完全由 Plan 插件决定——所以可以做到「点一下直接把 Plan 标签页打开并展开右侧栏」，不动对话、不动别的标签页。

### 位三（备选）：会话头部右上角那一排图标

- **是什么**：对话区顶部标题栏最右侧的一排小图标位。【文档已写明：`ui-conversation` 的 `conversation.session.header.utilities` 槽位】
- **有先例**：dsh-better-sidebar 的底部工作台开关、dsh-cost-meter 的花费显示都在这儿。【实测】

## 四、三个方案与各自的影响

### 方案 A：把 Plan 升为「一级页面」（左侧栏图标 + 中间区域整页）

**做法**：往位一注册一个 Plan 图标，同时往中间区域（`main` 槽位）注册一个 Plan 面板体。

| | 内容 |
|---|---|
| 效果 | 左侧栏出现一行 Plan 图标，点一下中间区域整块变成 Plan 页 |
| 代价 1 | 对话被顶掉——中间区域同时只能显示一个东西 |
| 代价 2 | **右侧栏整块消失**。这不是我保守估计，是硬事实：右侧栏的渲染逻辑第一行就是「有全局面板被选中时，我什么都不渲染」【实测：`ui-sidebar-right/src/client/shell/RightbarRoot.tsx`，`activePanelId === null` 才渲染】。也就是 Files / Git / 子代理 / 终端 / 浏览器，连同 Plan 标签页自己，全部不可见 |
| 代价 3 | 回对话的路径是「点左侧栏里任意一个会话行」——能回，但不显眼，用户未必知道【实测：`ui-workspace/src/client/navigation.ts` 的 `openSession` 里会调 `selectPanel(null)` 复位】 |
| 代价 4 | Plan 页跟的是「当前会话」，不再绑定到某个特定会话的标签页【我的推断】 |
| 改动量 | 插件内约 40–60 行（一个薄包装组件：从会话列表取当前会话 → 交给现有 PlanView；加两处槽位注册；加图标）。**不动 DSH 本体** |

**适合的场景**：把 Plan 当「整页工作台」用——进去专心看地图、串联画布、大表格，看完再回对话。信息密度大的内容在整页宽度下最舒服。

### 方案 B：保留现有标签页形态，加一个「一键直达」按钮

**做法**：往位二（或位三）注册一个按钮，点击后调用插件服务打开 Plan 标签页。

| | 内容 |
|---|---|
| 效果 | **三步变一步**。而且这一下不仅打开 Plan 标签页，还会**自动展开右侧栏**——因为打开标签页这个动作本身就把右侧栏展开写进了状态【实测：`ui-sidebar-right/src/client/stores.ts` 的 `openContent`，第一件事就是 `planSetExpanded(state, true)`】 |
| 代价 1 | Plan 仍是右侧栏宽度：默认约屏宽 45%，最小 300 像素、最大屏宽 70%【实测：`ui-layout/src/client/columns.ts`】。串联画布、宽表格这类横向内容依旧偏挤 |
| 代价 2 | 几乎没有。现有标签页、其他标签页、对话，全都不受影响 |
| 改动量 | 插件内约 25–35 行（一个按钮组件 + 一处槽位注册）。**不动 DSH 本体** |

**按钮放哪儿，两个候选**：

- **B1 左侧栏底部（设置齿轮旁）**——最贴近你说的「侧边栏一级别的按钮」；宽/窄两种侧边栏状态都渲染；有 dsh-cost-meter 的先例【实测】。
- **B2 会话头部右上角**——离你正在打字的地方近，抬头就能点；有 dsh-better-sidebar、dsh-cost-meter 的先例【实测】。

### 方案 C：A + B 并存

两个入口都做，现有标签页也保留。改动量约 70–90 行。你说的「**增加**入口」如果意思是「在现有基础上再加一条路，不要动现有的」，C 最贴合字面。

### 对比一览

| | 点击次数 | 对话是否还在 | 右侧栏其他标签页 | Plan 的宽度 | 改动量 |
|---|---|---|---|---|---|
| 现状 | 3 步 | 在 | 在 | 右侧栏（约 45% 屏宽） | — |
| **A** | 1 次 | **被顶掉** | **全部消失** | 整页 | 40–60 行 |
| **B** | 1 次 | 在 | 在 | 右侧栏（约 45% 屏宽） | 25–35 行 |
| **C** | 1 次（两个入口） | A 入口顶掉 / B 入口不顶 | 同左 | 两种都有 | 70–90 行 |

## 五、待拍板项

### ① 入口形态选哪个？

- **A**：左侧栏一级图标 + 中间区域整页（代价：对话与右侧栏都被顶掉）
- **B**：加一个一键直达按钮，保持现有标签页形态（代价：宽度仍是右侧栏）

**我的推荐是 B（先做 B1）**，理由：【我的推断】你这次说的是「**增加**入口」，不是「换个地方」；B 用最小的改动把「三步」变成「一步」，且不牺牲任何现有能力。如果你确实想要 Plan 当整页用（比如串联画布太挤），再补 A 或 C——两者不冲突，A 可以之后再加。

### ② 如果选了 B 或 C：按钮放哪儿？

- **B1**：左侧栏底部（设置齿轮旁）
- **B2**：会话头部右上角
- **B1 + B2**：都放

**我的推荐是 B1**，理由：【我的推断】它最接近你说的「侧边栏一级别的按钮」，而且左侧栏底部那块地方现在很空（只有设置齿轮和一个花费显示），不会跟别的图标抢位置。

### ③ 补充：一条官方文档核对后补上的风险（不影响 ① ② 的选择）

**依据**：`/dsh-knowledge` ch12「Slots」节 + Anti-Patterns 节【文档已写明】。逐条核对结论见 `.plan/参考-DSH-WebUI插件挂载点-20260921.md`。
