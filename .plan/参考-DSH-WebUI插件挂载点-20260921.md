## 二、官方文档怎么描述这套机制（原文要点）

**【文档已写明】** 出处：ch12 `### Slots（类型化 React 组合）`。

1. **注册表与生命周期**：`dsh-client-ui-slots` 定义不依赖 React 的注册表与类型代数；`SlotMap` 是**编译期注册表**，经声明合并写入 key、cardinality、scope、owner props、keyed props、可选 slot 级 inject face。注册与声明遵循 Cordis effect 生命周期：销毁 entry 移除贡献并递归折叠其声明的 child slots。**跨包贡献用 `ctx.slots.inject(key, callback)`**——callback 每段声明生命周期运行，owner 折叠时 effect 移除、重挂载时重跑。

   > 对我们的意义：Plan 插件挂进这些位，用的就是 `ctx.slots.inject(...)`，这与仓库里 `dsh-cost-meter` 的既有做法一致；不需要改 DSH 本体。

2. **Cardinality（基数）四型**：
   - `single`：单 cell，渲染 priority 胜者；需并列时声明 child slot 而非当列表。
   - `list`：必填 `id` 定址，排序按先 `order` 再注册顺序。
   - `keyed`：owner 传 `entryKey`，匹配 cell 按其 props 渲染。
   - `chain`：每 entry 纯 `select(owner)`，priority 序首个非 null 获选。
   - `priority` 对 single/list/keyed 是遮蔽优先级、对 chain 是选举顺序；**数值越小越先**。

3. **Scope（作用域）三型**：`root`（root 组件 + store 实例）、`session-maybe`（跟随当前选择，无 Session 仍可渲染）、`session`（要求可解析 Session binding，收到确定 Session 值）。

4. **组件输入（绝不收 `ctx`）**：`PropsRuntime<K>`、`PropsRenderSlots<S>`、`PropsStore<H>`、`InjectFace<I>`、`PropsLocale<N>`、`ComposedProps`。service/model object 留在 `apply` closure，只向组件投影 callback/observable source。

5. **框架 hooks 按 scope**（见下表）——注意 `usePanelInfo` 是**所有作用域**都有。

6. **各注入位用途**：owner 已知值走 owner props；单 entry callback/私有 observable 走注册项 `inject`；slot owner 控制、occupant 共享的能力走 slot 级 `inject`；跨 entry 共享/跨重挂载保留的可变视图状态走声明 store。

## 五、官方文档补的一条我漏掉的坑（重要）

**【文档已写明】** ch12 Anti-Patterns 原文：

> **把 single/keyed cell 当增量位复用**：`single` 与已有 occupant 的 keyed cell 是**替换点**；增量扩展用新 list `id` 或未占 key；复用现有 cell 表示**有意替换其展示**。`ctx.sidebarRightTabs` 同 `id` 二次注册、kind 其它撞名都抛错（除 builtin + extension 合法共存）。

**对我们的影响**：

- `sidebar.panellist` 是 **`list`** 型（必填 `id` 定址）→ 用**新 id** 就是「并列新增一行」，不会顶掉别人。上一轮方案 A 安全。【文档已写明】
- `sidebar.footer.action` 同是 **`list`** 型 → 同理安全。上一轮方案 B 安全。【文档已写明】
- `conversation.session.header.utilities` 也是 **`list`** 型 → 同理安全。【文档已写明】
- **但 `main` 是 `keyed` 型**：`conversation` 这个 key 已被 ui-conversation 占着。上一轮方案 A 用的是**新 key**（另起一个面板），所以是「新增一个面板」而非顶掉对话的既有 key——这一点上一轮说对了，但**没点明「复用已有 key 就会顶掉它」这层风险**。本文件补上：**绝不可复用 `conversation` 这个 key**。【文档已写明 + 我的推断】
